# AgentPager r4：Hermes 原生统计直读与空闲轮播

## 不安装 NAS 插件

PC Bridge 通过 Hermes 自带的 HTTP 接口读取统计，NAS 不安装统计插件，不开启新的监听端口，也不修改原有认证策略：

- `/api/analytics/usage?days=90`：原生日用量趋势。
- `/api/analytics/models?days=7|30|90`：各时段的全部模型统计，包含原生接口列出的辅助模型。

连接信息在 Bridge「设置 → Hermes 原生 HTTP 统计」中填写：完整服务地址（含端口）、可选 profile、访问令牌。地址不是模型 API 的 `/v1` 地址，而是 Hermes 服务本身的地址。访问令牌不得发到聊天里；只在本机设置窗口输入，程序用 Windows 当前用户 DPAPI 加密保存，不写进普通设置文件、日志或手机协议。HTTP 会明文经过网络；跨不可信网络应使用 HTTPS。原生服务拒绝认证时显示错误，不关闭认证、不扫描 PC 旧数据库、不回退到 NAS 插件。

## 数据页

- 顶部只显示 Codex / Claude / Hermes 页签，不再显示“数据”标题。
- 已连接、数据页可见且所有会话/子任务均无工作或待处理请求时，每页停留 10 秒轮换。任务工作、进入后台、断线、打开设置或离开数据页时暂停；手动操作后重新计时。
- Hermes 左侧显示所选时段 Token 最多的三个不同模型，条形分母是该时段全部已读取模型，不是前三名之和，也不是额度上限。
- 右侧时段总量独立汇总全部模型，不被左侧前三名截断。原生趋势接口的日序列与全模型时段汇总口径可能不同，程序明确标出原生接口限制，不编造缺失的逐日辅助用量或缓存写入数据。
- 原生接口没有历史逐请求思考深度，标为“深度未知”，不能把旧用量反推到当前 high 设置。
- API 价值属于参考估算，不是订阅账单；任何有用量模型缺少可靠价格时，不用已知模型的部分价格冒充全量费用。
- Claude 目前只有工作状态来源，暂无历史用量统计；缺失不等于零消耗。

## 工作状态

保留此前已经使用的 PC 客户端会话状态上报，不新增 NAS 统计插件。
异步子代理通过原生 `subagent.roster` 查询，按会话显示紫色“子代理工作中 · N 个”。即便主对话暂停生成，子代理未结束就不显示绿色完成，也不启动空闲数据轮播；读取失败不伪装为零或已完成。明确收到 `message.complete.status=complete` 后显示绿色完成；error/interrupted 显示已中断。单纯不忙、首次打开、切换焦点、断线不伪造成功，未观察到完成事件的旧会话仍可能显示空闲。新的工作状态会覆盖上次完成，不会一直卡在绿色。

## 升级

1. 托盘退出旧 Bridge，解压 Windows r4 并运行 `AgentPagerBridge.exe`。原配对、日志路径和自启动设置保留。
2. 在「设置 → Hermes 原生 HTTP 统计」填写 Hermes 服务地址及认证信息，保存并检查连接结果。
3. 若需完成状态修复，可用 HERMES 页面更新原有 **PC 客户端状态上报**。这与 NAS 统计插件不同；只看用量不依赖这一步。
4. 安卓覆盖安装 r4 调试 APK，不要先卸载，以免丢失配对。官方签名与调试签名不同，不能互相覆盖。
5. 浏览器扩展未改动，不必重装。

之前试装的 NAS 统计组件已经禁用并移除，本版不分发该组件。

## 验证边界

自动化测试、构建和签名验证以随包验证记录为准。没有连接安卓设备，不把 instrumentation APK 的编译说成真机运行；未替用户退出或替换正在运行的 Windows Bridge。未修改其他 Hermes profile。
